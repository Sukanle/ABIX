# ABIX-STD — cross-language ABI primitives

<p align="center">
  <a href="std_zh.md">中文</a> · English
</p>

ABIX-STD is the **standard cross-language ABI primitive layer**. It is not a
replacement STL and it does not put a standard library into every `.abix`. It
defines a small set of ABI types and contracts that different languages can
consume without each re-inventing a library interface.

See [`ABI-SPEC.md`](../../.agents/ABI-SPEC.md) §9.1 for the normative rules.

## Three data-passing semantics

| Semantics | Meaning | Who releases |
| --------- | ------- | ------------ |
| `borrow`  | non-owning view, valid only while the producer keeps the data alive | nobody — the receiver must not release |
| `owned`   | receiver takes ownership | the receiver, through the producer's declared release entry point |
| `copy`    | independent data from an explicit copy | the receiver owns the copy |

These are **contracts, not layouts**: they never change `TypeID` / `LayoutHash` /
`ABIHash`. They are carried by the ownership contract (`[[owned]]` /
`[[contract]]`) and are readable at run time from the metadata-region extension
directory.

## Contracts by capability, not by container

Contracts are matched by what a type can **prove**, never by a name table such as
`vector ↔ Vec ↔ ArrayList`:

| Contract          | Capability                       | Typical use                         |
| ----------------- | -------------------------------- | ----------------------------------- |
| `SequenceView<T>` | contiguous read/write view       | arrays, slices, vector borrowing    |
| `StringView`      | text bytes + length + encoding   | string args, parsing                |
| `Owner<T>`        | ownership + release protocol     | cross-DLL objects, resource handles |
| `Optional<T>`     | value may be absent              | optional args, query results        |
| `Result<T, E>`    | success or failure               | cross-language errors               |
| `Range<T>`        | iterable range                   | non-contiguous containers           |
| `MapView<K, V>`   | keyed lookup                     | associative containers              |
| `Opaque<T>`       | hidden representation            | special / custom containers         |

| Priority | Contracts                                                           |
| -------- | ------------------------------------------------------------------- |
| P0       | sequence view, string view, opaque handle, ownership, error boundary |
| P1       | optional, result, callback, generic range                            |
| P2       | map, set, deque, complex graphs, language-specific containers        |

P2 types are exposed through `Opaque` handles with accessors, capability
adapters, or explicit copies — **not** a unified implementation. A
`std::vector<T>` is not a contract of its own: AMC reads `data()`/`size()` and
lowers it to a `SequenceView<T>` when element type, layout, borrowing lifetime
and invalidation conditions allow; otherwise it uses `Opaque` or a copy.

```toml
[[view]]
type = "DemoBuffer"                  # opaque container layout
data_accessor = "demo_buffer_data"
size_accessor = "demo_buffer_size"
```

AMC generates a thin adapter (`DemoBuffer_view(value) -> abix_span_i32`) that
calls the accessors; the container's internal layout is never exposed.

## P1 contracts

P1 adds four contracts, each matched by capability (shape + element `TypeID`):

| Contract   | Layout / capability                                  |
| ---------- | ---------------------------------------------------- |
| `optional` | `{ discriminant: bool/u8; payload: T }`              |
| `result`   | `{ status: int; payload: T }` (reuses error boundary) |
| `callback` | `{ function entry; opaque context }`                 |
| `range`    | non-contiguous container via length + indexed access |

## First primitive: borrowed span

The ABIX-STD span is written as a source-level template:

```cpp
namespace abix_std {
template <class T> struct abix_span { const T *data; uint64_t len; };
}
typedef abix_std::abix_span<int32_t> abix_span_i32;   // the exported ABI entity
```

ABIX records the **concrete instantiation**, not the template. The frontend
instantiates it on request and AMC records the result under the exported name:

```toml
[[instantiate]]
template = "abix_std::abix_span"
args = ["int32_t"]
as = "abix_span_i32"
```

The concrete entity projects to the same layout in every language:

```rust
// Rust — generated by `amc generate -l rust`
#[repr(C)]
pub struct abix_span_i32 { pub data: *const core::ffi::c_int, pub len: core::ffi::c_ulonglong }
```

```zig
// Zig — generated by `amc generate -l zig`
pub const abix_span_i32 = extern struct { data: [*c]const c_int, len: c_ulonglong };
```

The producer keeps the backing memory alive and hands out a view; the consumer
reads it and never releases it. The ownership contract marks the interaction as
`borrowed`:

```toml
[[contract]]
function = "demo_numbers"
returns = "borrowed"
```

Instantiation and contract matching are separate: a successful instantiation of
`abix_span<int32_t>` does not by itself claim it satisfies the ABIX-STD
`SequenceView<i32>` contract; AMC proves compatibility or generates a thin
adapter. Declaring the contract makes AMC lower the concrete type:

```toml
[[instantiate]]
template = "abix_std::abix_span"
args = ["int32_t"]
as = "abix_span_i32"
contract = "sequence-view"     # -> direct
```

A record with the same two fields in a different order is `needs_adapter`, and
AMC generates the conversion to the canonical view:

```rust
pub fn abix_view_rev_i32_to_abix_span_i32(value: abix_view_rev_i32) -> abix_span_i32 {
    abix_span_i32 { data: value.data, len: value.len as _ }
}
```

Generic parameters are a frontend concern; see
[`LANGUAGE-PLUGIN.md`](../../.agents/LANGUAGE-PLUGIN.md) and
[`ABI-SPEC.md`](../../.agents/ABI-SPEC.md) §18.

## Second primitive: string view

`abix_str_utf8` is `{ const char *data; uint64_t len; uint32_t encoding; }`,
lowered against the `string-view` contract:

```toml
[[instantiate]]
template = "abix_std::abix_str"
args = ["char"]
as = "abix_str_utf8"
contract = "string-view"
element = "char"
```

The code unit is matched by the data pointer's pointee `TypeID`; the encoding is
a runtime value (the build checks the field's presence and type). It is
read-only and borrowed by default. `std::string_view`, Rust `&str` and Zig slices
are not treated as inherently equivalent — encoding, length unit, layout and
borrowing are verified first.

## Scope

In scope: the ABI types and contracts languages share (span, string view,
owned handle, result, callback). Out of scope: re-implementing a full STL,
defining a universal object model, or a runtime ownership system (see
[`AGENTS.md`](../../.agents/AGENTS.md) §1.3).

The end-to-end example lives in `AMC/tests/interop/`: one C++ library, one
`.abix`, and both a Rust and a Zig consumer reading the same borrowed span.
