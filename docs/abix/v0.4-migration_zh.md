# ABIX v0.4.0 迁移（从 v0.3.x）

<p align="center">
  中文 · <a href="v0.4-migration.md">English</a>
</p>

> **状态：v0.3.3 是最后一个 additive 的 0.3.x 版本。** v0.4.0 直接替换 `abix_optional`、`abix_result` 与 `abix_str` 的布局，不提供兼容层。旧的 `.abix` 产物与生成代码必须重新生成。

## 锁步关系

| AMC         | ABIX        | ABIX-STD | 动作                        |
| ----------- | ----------- | -------- | --------------------------- |
| `<= v0.3.2` | `0.3.x`     | 旧布局   | 保持旧 ref                  |
| `>= v0.3.3` | `>= v0.4.0` | 显式布局 | 重新生成 `.abix` 与生成代码 |

AMC v0.3.3+ 使用 `find_package(ABIX 0.4.0 CONFIG REQUIRED COMPONENTS runtime)`； ABIX v0.4.0 的 package version 会拒绝 `< 0.4.0`。

## 布局变化

### `abix_optional<T>`

```cpp
template<class T>
struct abix_optional {
    uint32_t discriminant;   // 0 = None, 1 = Some
    uint32_t reserved;       // 必须为 0
    alignas(T) T value;      // 仅当 discriminant == 1 时有效
};
```

- 只允许 `0` / `1`；其他值失败关闭；
- `reserved` 非零必须拒绝，不能忽略；
- `discriminant == 0` 时不得读取 `value`；
- `offset(value) = align_up(8, alignof(T))`，`alignof = max(4, alignof(T))`。

`int32_t` 实例：`offsetof(value) == 8`、`sizeof == 12`、`alignof == 4`。

### `abix_result<T>`

```cpp
template<class T>
struct abix_result {
    int32_t status;          // transport status
    uint32_t reserved;       // 必须为 0
    alignas(T) T value;      // status 等于契约 success 值时有效
};
```

- `status` 不是 16 字节的 `ErrorCode`；
- `reserved` 非零必须拒绝；
- `value` 的有效性由 `[[error]]` 契约定义。

### `abix_str<CodeUnit>`

```cpp
template<class CodeUnit>
struct abix_str {
    const CodeUnit *data;
    uint64_t len;
    uint32_t encoding;
    uint32_t reserved;       // 必须为 0
};
```

显式 `reserved` 把现有隐式 padding 明确化；非零 `reserved` 必须拒绝。

`abix_callback` 保持 additive：v0.4.0 保留 borrowed 形式与 `abix_callback_owned`，除非有单独的锁步决策替换它。

## 迁移清单

1. 用 AMC v0.3.3+ 重新生成所有 `.abix` 与生成代码。
2. 使用 ABIX v0.4.0 构建；package version 拒绝 `< 0.4.0`。
3. Rust/Zig adapter 改为显式 `#[repr(C)]` / `extern struct` 布局；先检查 `reserved`，再检查 discriminant 或 status。
4. 非法 discriminant、非零 reserved、未知 status 必须拒绝，不能 bitcast。
5. 不要跨版本复用 v0.3.x 的产物或生成代码。

## 为什么是破坏式版本

v0.3.x 的布局是 ABI 稳定的，但依赖隐式 padding 和单字节 optional discriminant。 v0.4.0 把 padding 显式化、加宽 optional discriminant，并增加 `reserved` 字段。不提供 `_v1` / `_v2` 别名，也不提供兼容层：新旧产物混用是布局错误，不是运行时回退。
