# ABIX v0.4.0 migration (from v0.3.x)

<p align="center">
  English · <a href="v0.4-migration_zh.md">中文</a>
</p>

> **Status: v0.3.3 is the last additive 0.3.x release.** v0.4.0 replaces the `abix_optional`, `abix_result` and `abix_str` layouts without a compatibility layer. Old `.abix` artifacts and generated code must be regenerated.

## Lockstep

| AMC         | ABIX       | ABIX-STD        | Action                                |
| ----------- | ---------- | --------------- | ------------------------------------- |
| `<= v0.3.2` | `0.3.x`    | old layout      | keep the old ref                      |
| `v0.3.3`    | `0.3.x`    | old layout      | additive transition release           |
| `>= v0.4.0` | `>= 0.4.0` | explicit layout | regenerate `.abix` and generated code |

AMC v0.4.0+ uses `find_package(ABIX 0.4.0 CONFIG REQUIRED COMPONENTS runtime)`; the ABIX v0.4.0 package version rejects `< 0.4.0`. AMC v0.3.3 stays on ABIX v0.3.x.

## Layout changes

### `abix_optional<T>`

```cpp
template<class T>
struct abix_optional {
    uint32_t discriminant;   // 0 = None, 1 = Some
    uint32_t reserved;       // must be 0
    alignas(T) T value;      // valid only when discriminant == 1
};
```

- only `0` and `1` are valid; anything else fails closed;
- non-zero `reserved` is rejected, not ignored;
- `discriminant == 0` must not read `value`;
- `offset(value) = align_up(8, alignof(T))` and `alignof = max(4, alignof(T))`.

For `int32_t`: `offsetof(value) == 8`, `sizeof == 12`, `alignof == 4`.

### `abix_result<T>`

```cpp
template<class T>
struct abix_result {
    int32_t status;          // transport status
    uint32_t reserved;       // must be 0
    alignas(T) T value;      // valid when status is the contract success value
};
```

- `status` is not the 16-byte `ErrorCode`;
- non-zero `reserved` is rejected;
- `value` validity is defined by the `[[error]]` contract.

### `abix_str<CodeUnit>`

```cpp
template<class CodeUnit>
struct abix_str {
    const CodeUnit *data;
    uint64_t len;
    uint32_t encoding;
    uint32_t reserved;       // must be 0
};
```

The explicit `reserved` makes the existing implicit padding explicit; a non-zero `reserved` is rejected.

`abix_callback` stays additive: v0.4.0 keeps the borrowed form and `abix_callback_owned` unless a separate lockstep decision replaces them.

## Migration checklist

1. Regenerate every `.abix` and every generated header/source with AMC v0.4.0+.
2. Build against ABIX v0.4.0; the package version rejects `< 0.4.0`.
3. Update Rust/Zig adapters to the explicit `#[repr(C)]` / `extern struct` layouts; decode `reserved` first, then the discriminant or status.
4. Reject an invalid discriminant, non-zero reserved and unknown status instead of bitcasting.
5. Do not reuse v0.3.x artifacts or generated code across the boundary.

## Why this is a breaking release

The v0.3.x layouts are ABI-stable but depend on implicit padding and a one-byte optional discriminant. v0.4.0 makes the padding explicit, widens the optional discriminant and adds `reserved` fields. There is no `_v1`/`_v2` alias and no compatibility layer: a mixed old/new artifact pair is a layout error, not a runtime fallback.
